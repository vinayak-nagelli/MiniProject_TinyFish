# LifePilot - Complete Project Documentation & Architecture Guide

This document explains every major file created in the **LifePilot** repository. It serves as a guide for your project review to explain *what* each file does and *why* it was built.

---

## 🏗️ 1. Backend Architecture (FastAPI & Python)
*Location: `lifepilot/backend/`*

### **Core Configuration & Setup**
*   **`app/main.py`**: The entry point of the backend server. It initializes FastAPI, configures CORS (so the React frontend can talk to it), manages the MongoDB startup/shutdown lifecycle, and registers all API routes.
*   **`app/core/config.py`**: Uses Pydantic to load and validate all `.env` secrets (like `GROQ_API_KEY`, `TINYFISH_API_KEY`, `MONGODB_URL`, and JWT secrets). It ensures the app crashes immediately if a key is missing, rather than failing silently later.
*   **`app/core/security.py`**: The security engine. It uses the `bcrypt` library to securely hash passwords before they enter MongoDB, and generates/verifies the JWT (JSON Web Tokens) used to keep users logged in securely.

### **Database Management**
*   **`app/db/mongodb.py`**: Manages the connection to the cloud MongoDB Atlas database. It uses `motor_asyncio` for non-blocking database queries and strictly injects `certifi` SSL certificates to ensure Windows compatibility.

### **Data Models (Schemas)**
*   **`app/models/user.py`**: Defines the exact structure of a User in MongoDB. It explicitly outlines the `UserProfile` schema so the database knows how to store complex arrays like `allergies`, `favorite_dishes`, and `saved_locations`.
*   **`app/models/schemas.py`**: Defines the data shapes for the AI logic. It ensures the Groq LLM always outputs the exact `UserIntent` (with the `agent_goal`) and that the web agents always return a strict `DealItem` format.

### **API Endpoints (Controllers)**
*   **`app/api/auth.py`**: Exposes the `/login` and `/register` endpoints. It handles password verification, user creation in MongoDB, and issues the JWT token.
*   **`app/api/user.py`**: Exposes the `/me/profile` endpoint. This allows the frontend Profile dashboard to save and fetch the user's AI constraints directly to/from MongoDB.
*   **`app/api/intent.py`**: The AI entry point. It receives the user's text prompt, securely grabs their hidden Profile constraints via their JWT token, and sends everything to Groq.
*   **`app/api/agent.py`**: The Execution endpoint. It receives the formulated AI intent, checks the user's `preferred_platforms`, and launches the Swiggy and Zomato agents in parallel to save time.

### **AI Services (The Brain & Muscle)**
*   **`app/services/groq_service.py`**: The Brain. Connects to Groq to run **LLaMA 3.3 70B**. It dynamically injects the user's profile (Allergies, Budget, Diet) directly into the system prompt to generate a highly compressed, speed-optimized goal for the web agent.
*   **`app/services/tinyfish_service.py`**: The Muscle. Connects to the TinyFish SDK. It takes the goal generated by Groq and spins up headless Chromium browsers in the cloud, autonomously navigating Swiggy/Zomato to extract the final deals.
*   **`app/services/ranker.py`**: The logic layer that takes the raw output from Swiggy and Zomato, calculates the "True Price" (Price + Delivery - Discount), and sorts them from best to worst.

## 🎨 2. Frontend Architecture (React, Vite, Tailwind)
*Location: `lifepilot/frontend/`*

### **Core Setup & State**
*   **`src/main.jsx`**: The Vite entry point that injects the React application into the browser DOM.
*   **`src/App.jsx`**: The traffic controller. It uses `react-router-dom` to manage navigation between the Home page and Profile page, and enforces the "Authentication Gate" so users cannot use the AI without logging in.
*   **`src/store/useStore.js`**: The global brain of the frontend using **Zustand**. It holds the user's session token, profile data, AI loading states, and the final extracted food deals so any component can access them instantly without prop-drilling.
*   **`src/services/api.js`**: The communication layer. It uses **Axios** to talk to the FastAPI backend. It contains a critical "interceptor" that automatically attaches the user's JWT token to every single request for seamless security.

### **Pages (Views)**
*   **`src/pages/Home.jsx`**: The main landing page. If logged out, it acts as a landing page with a call-to-action. If logged in, it displays the AI Command Input and dynamically renders the extracted results when the agents finish.
*   **`src/pages/Profile.jsx`**: The complex UI dashboard. It contains the interactive tabs for Diet, Locations, and Platform preferences, and directly syncs the user's input with the MongoDB backend.

### **Components (UI Building Blocks)**
*   **`src/components/CommandInput.jsx`**: The glowing search bar where users type their requests. It triggers the entire backend pipeline (`parseIntent` -> `runAgent`).
*   **`src/components/ResultCard.jsx`**: The UI card that beautifully displays a single food deal extracted by TinyFish, showing the restaurant name, price breakdown, and platform logo.
*   **`src/components/AuthModal.jsx`**: The animated popup overlay handling the Login and Signup forms, displaying errors if credentials are wrong.
*   **`src/components/NavBar.jsx`**: The top navigation header that conditionally shows the "Profile" link and "Logout" button only when authenticated.
*   **`src/components/Background3D.jsx`**: Uses `react-three-fiber` to render the floating, interactive 3D spheres in the background, giving the application a premium, futuristic aesthetic.
